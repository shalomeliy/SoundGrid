# v0.3.1 — מספר גרסה בקליינט ✅ (2026-09-03)

**נסגרה.** `npm run check` ירוק, `npm run build` נבדק ידנית מול ה‑bundle. הספק המקורי:
[`ROADMAP.md`](../../ROADMAP.md) (הבלוק הועבר לכאן עם הסגירה).

## מטרה

מספר הגרסה הרץ בקליינט תמיד זהה למקור האמת (`package.json`), בלי מחרוזת ידנית שנייה
שיכולה לסטות ממנו — עד עכשיו הקליינט לא הציג גרסה בכלל.

## מה נבנה

- **`vite.config.ts`** — קורא את `version` מ‑`package.json` בזמן build (`readFileSync`,
  לא `import` — נמנע מבעיית `resolveJsonModule` בפרויקט `node`) וחושף אותו כקבוע
  build‑time `__APP_VERSION__` דרך `define`. לא fetch בזמן ריצה, ולא דרך `core/` —
  זה נשאר פלטפורמה/build בלבד.
- **`src/vite-env.d.ts`** (קובץ חדש) — הצהרת `declare const __APP_VERSION__: string`,
  באותה צורה כמו `worklet-env.d.ts` הקיים.
- **`SystemPanel`** ב‑`src/app/components/Settings.tsx` — שורה קטנה `SoundGrid v{__APP_VERSION__}`
  בראש הלשונית System. לא בפריסה הראשית (אין מקום פנוי בגובה 710px, כמו שהוחלט
  ב‑ROADMAP).
- **`tests/repo/client-version.test.ts`** (חדש, 3 בדיקות) — `vite.config.ts` אכן מגדיר
  `__APP_VERSION__` ולא כותב את המספר כמחרוזת קשיחה לצידו; `Settings.tsx` באמת מציג
  את הקבוע; ואף קובץ מקור תחת `src/` לא כותב את מספר הגרסה הנוכחי כ‑string literal —
  כלומר בדיקה שתופסת עותק שני קשיח אם מישהו יוסיף אחד.

## מה נמדד

- `npm run check` ירוק (`tsc -b` + `oxlint` + `depcruise` + `vitest run`, 201 בדיקות
  ב‑19 קבצים לאחר ההוספה).
- `npm run build` רץ עד הסוף; נבדק ידנית עם `grep` על ה‑bundle שנוצר
  (`dist/assets/index-*.js`) — המחרוזת `["SoundGrid v", "0.4.0"]` (JSX children אחרי
  minify) נמצאת בפועל בקוד המיוצר, כלומר ה‑`define` אכן מוחלף במספר האמיתי מ‑
  `package.json` ולא נשאר placeholder.

## איך לבדוק בעצמך

1. להריץ את האפליקציה ולפתוח **Settings → System**.
2. בראש הלשונית אמורה להופיע שורה קטנה: **SoundGrid v0.4.0**.
3. הסימן שזה שבור: השורה לא מופיעה, או שהמספר לא תואם את `"version"` ב‑`package.json`.
