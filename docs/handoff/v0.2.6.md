# v0.2.6 — פתיחה עם הספרייה כבר טעונה ✅ (2026-09-02)

**נסגרה.** ביקור חוזר עם הרשאה בתוקף טוען את הספרייה **בלי אף לחיצה**; הרשאה
שפגה עולה ב**לחיצה אחת** ובשורה שמסבירה למה; משתמש חדש מקבל דיאלוג שנפתח כבר
בתוך תיקיית המוזיקה. האיפיון המקורי: [`ROADMAP.md`](../../ROADMAP.md), סעיף v0.2.6.

---

## הבאג שהגרסה הזאת נבנתה סביבו

‏`restoreLibraryFolder` **שאלה את ההרשאה וזרקה את התשובה**:

```ts
const perm = await handle.queryPermission({ mode: 'read' })
if (perm === 'granted') return { handle, name: handle.name }
return { handle, name: handle.name } // שני הענפים זהים
```

שני הענפים החזירו אותו אובייקט, אז האפליקציה לא יכלה להבדיל בין "אפשר לפתוח
עכשיו" לבין "צריך לחיצה" — וביקשה לחיצה תמיד.

**ולמה זה נהיה מלכודת ולא סתם חוסר נוחות:** ב‑Chromium, הבחירה
**"Allow this time"** לא הופכת בטעינה הבאה ל‑`denied`. היא הופכת ל‑`prompt` —
**בדיוק אותו ערך** של handle שמעולם לא אושר. ובנוסף, `requestPermission()` דורש
‏*transient user activation*: קריאה אליו מתוך `useEffect` בטעינת הדף לא מרימה
דיאלוג בכלל. כלומר קוד שמתייחס ל‑`prompt` כאל "פשוט תבקש שוב" מייצר **ספרייה
ריקה בלי שגיאה, בלי דיאלוג ובלי מילה על המסך** — הדילוג השקט שהפרויקט אוסר.

## מה נבנה

- **`src/core/library-boot.ts`** (חדש, טהור) — `bootFor`, `bootForScanError`,
  `bootCopy`. ממפה עובדות למצב ולמשפט. תשע מצבים: `checking` · `unsupported` ·
  `new` · `restoring` · `needs-click` · `blocked` · `missing` · `failed` · `loaded`.
- **`source-fsaccess/library.ts`** — `restoreLibraryFolder` מחזירה `permission`;
  ‏`pickLibraryFolder` מעבירה `startIn: 'music'` לצד `id`. ‏`id` גובר על `startIn`
  ברגע שיש תיקייה זכורה — כלומר ביקור ראשון נפתח ב‑Music, וכל ביקור אחריו נפתח
  איפה שהיו.
- **`app/state/store.ts`** — `library.boot` ו‑`library.bootDetail`.
- **`app/components/Library.tsx`** — האפקט בטעינה סורק **רק** כש‑`granted`;
  ‏`reconnect()` הוא המקום היחיד שקורא ל‑`requestPermission`, והוא מגיע מלחיצה.
  ‏`runScan` עוטף את הסריקה ב‑`try` ומסווג את השם של החריגה במקום להשאיר
  ‏rejection שקט.

## מה התגלה תוך כדי

1. **שלושה כפתורים לאותה פעולה.** במצב `needs-click` היו במקביל כפתור ראשי
   בכותרת, גלולה ירוקה לצידו, וכפתור במרכז — שלוש דרכי יציאה ממצב אחד. הכותרת
   מחזיקה עכשיו רק את *הבחירה האחרת* («Change folder»), והמצב מחזיק את שלו.
   הבדיקה `prompt: the panel asks once, not three times` מקבעת את זה.
2. **‏`window.indexedDB` ו‑`window.showDirectoryPicker` לא ניתנים להשמה.** הניסיון
   הראשון נכשל בשקט והבדיקות דיווחו "0 שורות" בלי שום שגיאה — אירוניה במקומה.
3. **הגרסה הזאת נכשלה בדיוק בכלל שהיא נכתבה בשבילו — והסקירה תפסה.**
   ארבעה מסלולים שבהם הדפדפן *זורק* לא היו עטופים: `queryPermission` על תיקייה
   שנמחקה, ‏`IndexedDB` שלא נפתח (חלון פרטי, אחסון חסום, פרופיל פגום),
   ‏`requestPermission` שאיבד activation, וסריקה שנפלה. אין `catch` → אין
   ‏rejection מטופל → **הפאנל נתקע על «Looking for your library…» לנצח, בלי
   שגיאה, בלי דיאלוג ובלי מילה.** ‏`reportFailure` ב‑`Library.tsx` הוא התיקון,
   וארבעת המסלולים הם עכשיו בדיקות קבועות בסקריפט. **כל באג שנתפס פעם אחת הופך
   לבדיקה קבועה** — זה המקרה.
4. **הנוסח הבטיח אופציה שלא תמיד קיימת.** הכתובית אמרה «אם בחרת *Allow on
   every visit*» — אבל הדיאלוג שהמשתמש קיבל בפועל הציע **Allow / Don't Allow
   בלבד**. הדפדפנים נותנים את ההרשאה הקבועה רק בתנאים מסוימים, אז הנוסח מתאר
   עכשיו את שני המקרים במקום להבטיח אחד.
5. **הודעה שקיימת ב‑DOM אבל מתחת לקו הקיפול היא עדיין שקט.** ‏`EmptyState`
   ממורכז בתוך פאנל שיכול להיות גבוה מהחלון. נוספה בדיקה שהמשפט **נראה**
   ‏(`getBoundingClientRect` בתוך `innerHeight`) בשלושה גדלי חלון, לא רק קיים.
6. **סעיף v0.1.7 נסגר בדרך אגב.** הצורך לראות טבלה עם תוכן הוליד מחולל ID3v2.3
   בתוך הבדיקה, וזה בדיוק מה שחסר כדי לאמת את שבע העמודות בעין.
